## 1. エグゼクティブサマリー

### 1.1 プロダクトコンセプト

**AI Agent Teams Platform** は、複数の専門AIエージェントが「開発チーム」として協調し、ソフトウェア開発タスクを自律的に遂行するプラットフォームである。

従来の単一 AI アシスタント（コード補完・チャット型）とは根本的に異なり、テックリード・コーダー・レビュアー・テスター・ドキュメンテーション担当といった専門エージェントが役割分担し、人間の開発チームと同様のワークフロー（設計→実装→テスト→レビュー）を自律的に回す。

### 1.2 なぜ今か

1. **AI エージェント元年**: 2024-2025年にかけ、単発のコード補完から「自律的にタスクを遂行する AI エージェント」へと市場の重心が移動
2. **単一エージェントの限界が顕在化**: コンテキストウィンドウ制約・品質劣化により、複雑なタスクには複数専門エージェントの協調が必要
3. **Claude Code の Agent Teams 基盤**: 本リポジトリで有効化済みの実験的機能を発展させ、市場投入する好機

### 1.3 主要数値（Year 1 目標）

| 指標 | 目標値 |
|------|--------|
| MAU | 50,000 |
| 有料顧客数 | 3,000 アカウント |
| ARR | $10M+ |
| タスク完了成功率 | 75%+ |
| NPS | 50+ |

## 2. 市場分析

### 2.1 市場規模と成長性

**TAM（Total Addressable Market）：AI ソフトウェア開発ツール市場全体**

- 【仮定】2025年時点のグローバル AI コーディングアシスタント市場規模は約 **70〜90億ドル**（Grand View Research、MarketsandMarkets 等の推計を参考に推定）。
- 2028年までに **250〜300億ドル** 規模への成長が見込まれる（CAGR 約30〜35%）。
- この中には、コード生成、コードレビュー、テスト自動化、ドキュメント生成、デバッグ支援、エージェント型開発ツール等が含まれる。

**SAM（Serviceable Available Market）：マルチエージェント型 AI 開発支援ツール**

- 【仮定】TAM のうち、CLI ベースかつエージェント協調型の開発支援ツールを求めるプロフェッショナル開発者セグメントは市場の約 **15〜20%** と推定。
- 2025年時点で約 **10〜18億ドル**、2028年には **50〜60億ドル** に拡大する見込み。

**SOM（Serviceable Obtainable Market）：初期獲得可能市場**

- 【仮定】Anthropic のブランド力、Claude のモデル性能、既存の Claude Code ユーザーベースを前提に、ローンチ後12ヶ月で SAM の **3〜5%** を獲得可能と推定。
- 初期 SOM は **3,000万〜9,000万ドル**（年間売上ベース）。

**AI 開発ツール市場のトレンド**

1. **シングルショットからエージェントへの進化**: 2023年はコード補完（Copilot 型）が主流だったが、2024〜2025年にかけて「自律的にタスクを遂行する AI エージェント」へと市場の重心が移動。
2. **マルチエージェント協調の台頭**: 単一エージェントでは複雑なタスクの品質に限界があり、複数エージェント協調アーキテクチャへの需要が急増。
3. **CLI / ターミナルファーストの回帰**: 開発者のネイティブなワークフロー（ターミナル、シェル）に統合される CLI ツールが再評価されている。
4. **エンタープライズ採用の加速**: 【仮定】Fortune 500 企業の **60%以上** が何らかの AI コーディング支援ツールを試験導入済み。
5. **コスト効率への注目**: API 呼び出しコストの最適化、ローカル推論との組み合わせなど、実用的なコスト管理が差別化要因に。

### 2.2 ターゲットユーザー

#### プライマリペルソナ：「田中 裕太」— テックリード / シニアソフトウェアエンジニア

| 項目 | 詳細 |
|------|------|
| **年齢** | 30〜40歳 |
| **役職** | テックリード、シニアエンジニア、スタッフエンジニア |
| **企業規模** | 50〜500名のテック企業、またはエンタープライズの開発部門 |
| **技術スタック** | TypeScript / Python / Go、Git、CI/CD パイプライン |
| **開発環境** | ターミナル中心。Neovim または VS Code + 頻繁なターミナル操作 |
| **AI ツール経験** | GitHub Copilot を1年以上使用。Cursor も試用経験あり |
| **チーム状況** | 5〜10名のチームをリードし、コードレビュー・設計判断・実装を兼任。慢性的に時間が足りない |
| **年収** | 800〜1,500万円（日本）/ $150K〜$250K（米国） |
| **心理特性** | 「AIに丸投げ」ではなく「AIと協働」したい。品質と制御可能性を重視 |

**Agent Teams で変わるユーザージャーニー**:

1. タスクを定義する → Agent Teams が「設計エージェント」「実装エージェント」「テストエージェント」「レビューエージェント」に分担して並列実行
2. 各エージェントの出力を確認し、フィードバックする → 人間はオーケストレーターに徹する
3. 最終的な意思決定と承認のみ人間が行う

#### セカンダリペルソナ

| ペルソナ | 概要 | 主な動機 |
|---------|------|---------|
| **Emily — スタートアップ CTO** | 1〜5名の極小チーム。AI を「仮想チームメンバー」として活用 | 一人で複数人分のアウトプット。月額 $50〜$200 の予算感 |
| **鈴木部長 — エンタープライズ開発部門長** | 50〜200名規模の開発組織。開発生産性 KPI の改善がミッション | ROI の定量化。セキュリティ・コンプライアンス要件 |
| **Alex — DevOps / SRE** | インフラ構成管理・CI/CD・モニタリング設定の自動化 | Terraform / K8s マニフェスト生成・レビューに Agent Teams 活用 |

#### ユーザーの課題（ペインポイント）

1. **コンテキストの断片化**: ツールごとにコンテキストが分断され、情報の受け渡しに認知負荷がかかる
2. **単一エージェントの品質限界**: ロングコンテキストで後半のタスクほど品質が劣化する
3. **レビュー待ちのボトルネック**: 人間のコードレビュアーの稼働率が開発速度のボトルネック
4. **AI 出力の制御不能感**: 既存ツールは判断過程が不透明。エンタープライズでは説明責任が必要
5. **ツール統合の煩雑さ**: IDE・ウェブUI・API 間を行き来する非効率
6. **コスト予測の困難さ**: API トークン消費量が予測しづらい

### 2.3 競合分析

#### 直接競合

| 競合 | 強み | 弱み |
|------|------|------|
| **GitHub Copilot Workspace** | GitHub エコシステム統合。150万人超のユーザーベース | GitHub ロックイン。マルチエージェント協調は限定的 |
| **Cursor** | 優れた UX。ARR $100M 突破と報道【仮定】 | エディタロックイン。CLI 統合が弱い |
| **Devin (Cognition)** | 高い自律性。先行者優位のブランド | 【仮定】精度・信頼性に課題。ブラックボックス的 |
| **Windsurf (Codeium)** | 無料ティアからのアップセルパス | エディタ固有。エンタープライズ実績限定 |
| **Aider** | CLI ネイティブ。OSS で透明性が高い | 単一エージェント。エンタープライズサポートなし |

#### 間接競合

| カテゴリ | 具体例 | 脅威度 |
|---------|--------|--------|
| 汎用 LLM チャット | ChatGPT、Claude ウェブ版、Gemini | 中 |
| ローコード / ノーコード | Retool、Bubble、v0.dev | 低〜中 |
| OSS エージェントフレームワーク | AutoGen、CrewAI、LangGraph | 中〜高 |

#### 差別化ポイント

1. **マルチエージェント協調のネイティブサポート**: 専門化された複数エージェントが協調し、単一コンテキストウィンドウの制約を超える
2. **CLI / ターミナルネイティブ**: エディタロックインなし。パイプラインやスクリプトへの組み込みが容易
3. **Claude モデルの品質**: SWE-bench 等でトップクラス。長文コンテキスト理解、指示追従性、安全性で高評価
4. **透明性と制御可能性**: 各エージェントの思考過程・判断根拠が可視化。開発者が「オーケストレーター」として制御権を維持
5. **段階的な自律性（Graduated Autonomy）**: 権限レベルを細かく制御可能。エンタープライズのセキュリティポリシーに適合
6. **Anthropic のセーフティブランド**: 規制産業での導入障壁を低下

## 3. プロダクト概要と技術設計

### 3.1 プロダクトビジョン

**コンセプト**

AI Agent Teams Platform は、複数の専門性を持つAIエージェントが「チーム」として協調し、ソフトウェア開発ライフサイクル全体を自律的に遂行するプラットフォームである。本リポジトリの `.claude/settings.json` に定義された `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` 機能を発展させ、エンタープライズ向けのスケーラブルなマルチエージェント開発プラットフォームとして提供する。

**コアバリュー**

1. **協調的自律性**: 専門エージェント群の協調により、単体では実現困難な精度と網羅性を達成
2. **人間中心のオーケストレーション**: `teammateMode: "auto"` のような自動モードと、人間介入モードのシームレスな切替
3. **透明性と追跡可能性**: エージェント間のすべてのやり取り・意思決定・コード変更を事後検証可能
4. **漸進的導入**: 既存ワークフロー（Git、CI/CD、コードレビュー）を置き換えるのではなく、その中に組み込む

---

### 3.2 主要機能

#### MVP に含む機能

1. **エージェントロール定義・チーム編成機能** — テックリード、コーダー、レビュアー、テスター、ドキュメンテーション担当等のプリセットロール + カスタムロール定義
2. **タスク分解・割当エンジン** — Issue / ユーザーストーリーを自動サブタスク化。依存関係解析と実行順序最適化
3. **エージェント間メッセージング・コンテキスト共有** — 構造化メッセージによるコンテキスト伝達基盤
4. **コードベース統合ワークスペース** — Git リポジトリとの統合。競合検知と自動マージ支援
5. **レビュー・承認ワークフロー** — エージェント間クロスチェック + 人間の承認ゲート
6. **実行ダッシュボード・オブザーバビリティ** — リアルタイム可視化（進捗、通信ログ、コスト）
7. **セーフガード・ロールバック機構** — サンドボックス実行、破壊的操作の自動検知・阻止

#### 将来拡張機能

- マルチリポジトリ対応（マイクロサービス構成）
- 学習・適応機構（過去プロジェクトからの最適化）
- 外部ツール連携（Jira、Slack、Datadog、Sentry）
- カスタム LLM バックエンド（GPT、Gemini、OSS モデル）
- 自然言語によるチーム指揮（高レベル指示→チーム編成→実行を一気通貫）

#### 技術スタック

| レイヤー | 技術選定 | 選定理由 |
|---------|---------|---------|
| フロントエンド | React + TypeScript, Vite | リアルタイムダッシュボードに適した宣言的 UI |

| キャッシュ | Redis 7 | セッション管理、コンテキストキャッシュ、分散ロック |
| オブジェクトストレージ | MinIO (S3互換) | クラウド環境では AWS S3 / GCS に置換可能 |
| コンテナ実行 | Docker + gVisor | セキュアなサンドボックス隔離 |
| オーケストレーション | Kubernetes (EKS/GKE) | 水平スケーリング、自動復旧 |
| 監視 | OpenTelemetry + Grafana + Loki | 分散トレーシング、メトリクス、ログ統合 |

**通信パターン**:
1. **Request-Reply**: タスク割当→完了報告（タイムアウト付き）
2. **Publish-Subscribe**: ステータス更新の全エージェントブロードキャスト
3. **Work Queue**: 同一ロール間のタスク負荷分散
4. **Escalation Chain**: 解決不能問題の段階的エスカレーション

#### スケーラビリティ設計

1. **水平スケーリング**: ステートレスエージェント + Kubernetes HPA。【仮定】初期同時稼働チーム数 50、エージェント総数 250
2. **非同期・イベント駆動**: NATS JetStream 経由の非同期メッセージング。障害時はキュー保持→復旧後再処理
3. **階層型コンテキスト管理**: 要約・圧縮保持 + オンデマンド展開。pgvector によるベクトル検索
4. **コスト制御**: エージェント/チーム/プロジェクト単位のトークン上限設定。【仮定】Prompt Caching でコスト 40-60% 削減
5. **マルチリージョン対応（将来）**: データレイヤー設計段階からリージョン分離を考慮

### 3.4 非機能要件

#### パフォーマンス目標

| 指標 | 目標値 |
|------|--------|
| タスク割当レイテンシ | < 2秒 |
| エージェント間メッセージ配信 | < 100ms (p99) |
| ダッシュボード初期描画（LCP） | < 3秒 |
| ステータス更新反映 | < 500ms |
| API レスポンスタイム | < 200ms (p95) |
| 【仮定】同時接続チーム数 | 50チーム / クラスタ |

#### セキュリティ要件

- **認証・認可**: OAuth 2.0 / OIDC + RBAC。エージェント操作権限はポリシーファイル（`.claude/permissions.json`）で制御
- **コード・データ保護**: TLS 1.3（転送時）+ AES-256（保存時）。厳密なスコープ制御
- **サンドボックス実行**: gVisor コンテナ内。ネットワーク隔離。破壊的操作は人間承認必須
- **監査・コンプライアンス**: 改ざん不可能な監査ログ（最低1年保持）。【仮定】SOC 2 Type II を GA までに取得

#### 可用性・信頼性

- **SLA**: 【仮定】MVP 段階 99.5% → GA で 99.9%
- **障害耐性**: エージェント障害時の自動タスク再割当。NATS 永続化によるメッセージ喪失防止
- **チェックポイント・復旧**: 各段階でチェックポイント取得。Git コミット単位での復元
- **ディザスタリカバリ**: 【仮定】RPO 1時間、RTO 4時間

## 6. リスクと対策

### 技術リスク

| リスク | 深刻度 | 発生確率 |
|--------|--------|----------|
| LLM の幻覚問題（マルチエージェント間での伝播・増幅） | 高 | 高 |
| エージェント間デッドロック・無限ループ | 高 | 中 |
| サンドボックスのセキュリティ脆弱性 | 高 | 中 |
| LLM API の可用性・レート制限の波及 | 中 | 高 |
| 推論コストの急騰 | 中 | 中 |

### 市場リスク

| リスク | 深刻度 | 発生確率 |
|--------|--------|----------|
| 大手プラットフォーマーの参入（Copilot Workspace, Google, Amazon） | 高 | 高 |
| 開発者の心理的抵抗（AI 自律コード変更への不信） | 高 | 中 |
| PMF 未達（マルチエージェントの付加価値が実感されにくい） | 高 | 中 |

### 規制リスク

| リスク | 深刻度 | 発生確率 |
|--------|--------|----------|
| AI 規制強化（EU AI Act で「高リスク AI」分類の可能性）【仮定】 | 高 | 中 |
| 知的財産権・著作権問題 | 高 | 中 |
| データプライバシー（GDPR / 個人情報保護法） | 中 | 高 |

### 対策

**技術リスク対策**:
1. **多層検証アーキテクチャ**: 専用「検証エージェント」必須配置。クロスチェック + ヒューマンインザループ
2. **サーキットブレーカー**: 最大ステップ数・実行時間・コスト制限。ループ検出アルゴリズム
3. **セキュリティ多層防御**: gVisor/Firecracker、ネットワーク分離、定期ペネトレーションテスト
4. **マルチプロバイダー戦略**: 複数 LLM プロバイダー対応。自社ファインチューニングモデル開発

**市場リスク対策**:
1. **差別化の徹底**: 「チーム協調」に集中。オープンプロトコル標準化を主導
2. **スイッチングコスト構築**: カスタムエージェント蓄積、組織固有ワークフロー学習
3. **段階的信頼構築**: 低リスクタスクから導入→実績に基づき権限拡大

**規制リスク対策**:
1. **プライバシーバイデザイン**: ゼロリテンションポリシー。データ処理地域選択オプション
2. **コンプライアンスプログラム**: AI 規制動向の継続モニタリング。EU AI Act 事前対応
3. **IP 保護機能**: ライセンス適合性チェック。学習データ由来コード検知フィルタ
