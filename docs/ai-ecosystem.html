Claude-Code のAI路線図

依頼は左から右へ11列を通って形になります。入口は Claude アプリと毎朝の定期タスク。司令塔の Claude Code が受けた依頼は、ハーネスを通ってから4つの路線に分かれる。アプリを作る路線、スキルで作る路線、外部サービスを操作する路線、外部APIを呼ぶ路線です。下の棚には、毎回読んで書き戻すルールと資産を置いています。

  • 入口は Claude アプリと定期タスク、作業はクラウドのコンテナ
  • 危ない操作は guard が止めるか、あなたの確認に回す
  • 外に出す操作は承認ゲートで、必ずあなたが決める
  • 毎朝6時50分に新問の候補が3つ届く
  • 鍵は .env の1か所、Claude Code は中を開かない
  • 完了の前にテスト447件と検品係を通す
  • 記録が残るのは GitHub、セッションは毎回消える
路線
横にスクロールするか、ドラッグして動かせます。駅にカーソルを置くと、その駅を通る線だけが残ります。

2枚の図から取り入れたもの、まだないもの

KEITO版は司令塔1つに道具が枝分かれする形で、かいさんの図は分野ごとに担当のAIを置き、本人は承認に徹する形でした。骨組みは違っても、定期で動く入口と、外に出す前の承認はどちらにもある。この2つを先に入れました。

  1. 入れた

    定期実行

    フリオチ新問の朝便が、毎朝6時50分にリポジトリを持った実行用セッションで動きます。新問を3つ作って機械検査と検品係に通し、残ったものを furiochi-candidates ブランチに置く。試運転で最初の3問がもう届いています。バンクには入れず、採るかどうかはあなたが決めます。

  2. 入れた

    承認ゲート

    PR とマージ、デプロイと公開、外部へのデータ送信、共有と削除、定期タスクの変更は、guard.py が必ずあなたの確認に回します。課金と契約はツールで見ていないので、CLAUDE.md の決まりで止めています。

  3. 次に足すならこれ

    公開先

    候補が毎朝届いても、遊ぶのがあなた1人では問題バンクが育つだけです。Streamlit Cloud などで人に使ってもらうには、履歴が1つのJSONに共有されてしまう点を先に直す。README の未実装にも書いてある課題です。

  4. 別のAIによるレビュー

    KEITO は大きい成果物を Codex と Antigravity にも見せてから公開している。ここの kenpin は同じ Claude の別の目でしかありません。違うモデルの指摘を混ぜるには、PCに Codex CLI か Gemini CLI を入れて、入れたほうのサービスと契約する必要があります。

  5. 分野ごとの担当AI

    かいさんは研究、サイト運営、創作、暮らし、開発に1体ずつ置いている。別々に走り続ける関心が4つ5つと並んだら分ける価値が出ます。今はアプリ開発がほぼ1本なので、司令塔1つで足ります。

  6. 速い判断AI

    KEITO の Jev は依頼を0.2〜0.35秒で読み、種類や取り返しのつかなさを点数にする。ここでは guard.py の決まりで代わりをさせています。決まりで拾えない曖昧な依頼が増えてきたら考えます。

出典は .claude の settings.json・hooks・agents・skills と、CLAUDE.md、furiochi_lab、enneagram_tool、tests、このセッションにつながっているコネクタ。下敷きにしたのは、ふっく氏の投稿で紹介された KEITO のAIエコシステムの図と、Mojofull 氏が投稿した、かいさんとAIエージェントたちの運用アーキテクチャ図です。
