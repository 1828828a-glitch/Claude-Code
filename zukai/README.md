トヨマネ（@toyomane）さんが Claude で作った図解「AIは、用がなくても話すもの」と、その作り方を説明した2枚のスライドを手元で組み直したもの。

- 図解 https://x.com/toyomane/status/2118984186279366843
- 作った流れ https://x.com/toyomane/status/2118990829989798196

できあがる画像は3枚。

| ファイル | 中身 | 大きさ |
| --- | --- | --- |
| `out/zukai.png` | 図解の完成版 | 2160×2880（縦長3:4） |
| `out/slide1.png` | ①ざっくり書いて、素材を渡して、大枠を作ってもらう | 3840×2160 |
| `out/slide2.png` | ②粘り強く何度もフィードバックして、たまに褒める | 3840×2160 |

スライド2に並ぶ5枚の縮小図は、スクリーンショットの貼り付けではない。同じデータから1回目〜5回目の版を描き分けている。元のスライドにある「次への指摘」をそのまま切り替えスイッチにした。

| 版 | 直したこと |
| --- | --- |
| 1 初版 | イラストが見出しや吹き出しに重なっている。段の並びも今と違う |
| 2 上下に矢印 | 矢印を足したが、上下につないでしまった |
| 3 左右の矢印と色 | 左右をつなぎ、BEFORE はグレー、AFTER は青に塗り分け、タイトルを濃くした |
| 4 チャット形式 | 会話を4往復の雑談にした。ただし3つのかたまりが詰まっている |
| 5 かたまりを整理 | 会話・対比・まとめの間に余白をとって完成 |

## 作り方

```bash
node zukai/build.js                                   # 既定のデータで作る
node zukai/build.js 自分の図解.json --out 出力先        # 別のデータで作る
node zukai/build.js --no-png                          # HTML だけ書き出す
```

Playwright が入っていれば PNG まで作る。入っていなければ `out/html/` の HTML をブラウザで開けば見られる。フォントは Google Fonts の Montserrat と M PLUS Rounded 1c を読み込むので、ネットにつながった状態で動かす。

## イラストについて

元の図版はいらすとやの素材を使っている。いらすとやの絵はリポジトリに入れられないので、ここには同じ役どころの人物を自作の SVG（`illust.js`）で入れてある。手元にいらすとやの絵を置けば、そちらに自動で切り替わる。

```bash
node zukai/fetch-irasutoya.js     # いらすとやから7点を zukai/assets/ に取ってくる
node zukai/build.js               # assets/ にある役は画像、ない役は SVG で描く
```

| 役の名前 | 自作 SVG の中身 | いらすとやで使う絵 |
| --- | --- | --- |
| `worker_tired` | ノートPCに向かう疲れた会社員 | パソコンで目が疲れた人のイラスト（男性） |
| `ai_blank` | 頭が脳のモニターになった人形 | 人工知能のキャラクター |
| `man_coffee` | コーヒー片手にくつろぐ会社員 | いろいろなコーヒーで一服している人のイラスト（男性会社員） |
| `ai_desk` | 資料に囲まれて書き物をする AI | 学ぶ人工知能のイラスト |
| `salesman_run` | かばんを持って走る営業 | 急いで走る会社員のイラスト（男性） |
| `man_paper` | にこにこ顔で資料を差し出す部下 | 有給休暇を申請する人のイラスト（男性）※紙の文字を消して使う |
| `boss_crossed` | 腕を組んで資料をにらむ上司 | 考え事をしている男性会社員のイラスト |

`zukai/assets/` に役の名前と同じファイル名（`worker_tired.png` など）の画像を置けば、どの絵でも差し替えられる。置き場所は環境変数 `ZUKAI_ASSETS` で変えられる。BEFORE 側と、03 の上司はグレーにして使う。ビルドのたびに、手元の画像を何点使ったかを表示する。

いらすとやの規約（https://www.irasutoya.com/p/terms.html ）で効いてくるのは次の3つ。

- 素材の再配布は、加工の有無にかかわらず禁止。だから `zukai/assets/` は .gitignore に入れてあり、画像は使う人がそれぞれ自分の手元に取ってくる
- 商用で使うなら、1つの作品に使えるのは20点まで（同じ絵の重複は1点）。非商用なら点数の制限はない
- 加工は、いらすとやの絵だとわかる範囲なら可。`man_paper` は紙に書かれた「有給休暇申請」の文字だけを白く塗り、点線に置き換えている

リポジトリに入っている出力画像（`out/`）は、すべて自作 SVG 版で描いたもの。

## データの書き方

`examples/ai_hanasu.json` がそのまま見本になる。`[[ ]]` で囲んだところが青くなり、`\n` で改行する。

- `diagram.title` タイトル。例 `"AIは、[[用がなくても話す]]もの"`
- `diagram.before` と `diagram.after` 見出し、会話（`chat`）、会話の下の注記（`note`）。`draft` は1〜3回目の版で使う短い場面
- `diagram.rows` 左右を矢印でつなぐ3段の対比。`label` は段の上に出る小見出し
- `diagram.callout` 一番下のたとえ話
- `stages` スライド2の各版の名前・反応・次への指摘
- `slides` スライド1に載せる最初のテキスト、指示、素材、まとめ

## 記事の図版を再現する deck.js

同じくトヨマネさんの記事「AIでゴミを量産する人になるな」に載っている図版を、記事の順に並べ直したもの。最後の新刊の広告だけは外した。

元の投稿 https://x.com/toyomane/status/2118998896190099560

```bash
node zukai/deck.js                                    # zukai/out/workslop/ に8枚
node zukai/deck.js 自分の資料.json --out 出力先
```

| ファイル | 中身 |
| --- | --- |
| `01-cover.png` | 見出し画像「AIでゴミを量産する人にならない方法」（3000×1200） |
| `02-slop.png` | わざと盛ったAIポン出し資料の見本。3D風の図とびっしりの箇条書き |
| `03-handoff.png` | スタンスなき「AIポン出し」で中間管理職が疲弊している |
| `04-statement.png` | 既知の情報の再整理や、意志が込められていないアウトプットの価値がゼロに近づく |
| `05-expand.png` | あるべきアウトプットのあり方が変わり、前後に価値が染み出す |
| `06-process.png` | 資料作成はスキルの総合格闘技（目に見える工程と実際の工程） |
| `07-three.png` | AI時代に人間に求められるスキルは「3CON」 |
| `08-compare.png` | ケーススタディ。同じ提案でも、3CONの有無で結果が変わる |

スライドは `examples/workslop.json` に1枚ずつ書き、`"type"` でレイアウトを選ぶ。cover・slop・handoff・statement・expand・process・three・compare の8種類があり、どれも中身の文字を差し替えればそのまま自分の資料に使える。process の `"focus"` は灰色で目立たせる工程の番号（0始まり）。

元のスライドの右上にある会社のロゴと、左下の著作権表示は入れていない。代わりに左下へ原案のクレジットを置いた。03 の真ん中に流れていく資料の束は、02 と同じものを縮小して重ねている。

## Markdown の原稿からスライドを作る md2slides

DevelopersIO の記事「登壇当日に Claude for Google Workspace で Markdown 原稿をスライドに変換して間に合わせた話」（emi さん）と同じやり方を、手元で動く形にしたもの。紹介元の投稿 https://x.com/Tak1wa/status/2114718854131888148

記事のやり方は、テンプレートの見本スライドを複製して文字だけ差し替える、というもの。新しいレイアウトは作らない。md2slides も同じで、出力は Google スライドや PowerPoint でそのまま手直しできる .pptx になる。

```bash
pip install python-pptx
python3 zukai/slides/md2slides.py zukai/examples/talk.md                          # zukai/out/slides/talk.pptx
python3 zukai/slides/md2slides.py 原稿.md --template 会社のテンプレート.pptx --out 出力.pptx
```

原稿は `---` でページを区切る。ページの種類は見出しで決まる。

| 原稿のページ | 使う見本 |
| --- | --- |
| `# タイトル` のあるページ（続く1行目が副題、残りが発表者の欄） | 表紙 |
| `## 小ネタ 1` と `## 題名` の見出し2つだけのページ | 中扉 |
| 最後の、見出しだけ（と画像）のページ | 表紙（裏表紙として） |
| それ以外 | 本文。`##` がタイトルになり、残りが本文の枠に入る |

本文の枠には、箇条書き（親は●、子は○）、番号付きリスト、段落、コードブロック（黒地に等幅）、表（罫線付き）、画像が入る。画像のファイルがあれば貼り、なければ「画像を手動で挿入」の枠を置く。枠に収まらなければ字を縮め（本文14pt・コード9pt・表10ptが下限）、それでも無理なら「（続き）」のスライドに分ける。最後に、原稿のどのページをどの見本から作ったかの対応表を `<名前>-map.md` に書く。

見本スライドは、スライドに書かれた目印の文字で見分ける。手持ちのテンプレートを使うときは、見本にしたいスライドの枠にこの目印を書いておく。目印のない飾りやロゴはそのまま複製され、テンプレートにもとからあるスライドは出力から外れる。

| 見本 | 目印 |
| --- | --- |
| 表紙 | `{{title}}` `{{subtitle}}` `{{presenter}}` |
| 中扉 | `{{section_label}}` `{{section_title}}` |
| 本文 | `{{title}}` `{{body}}`（`{{body}}` の枠の位置と字の大きさが本文の基準になる） |

同梱のテンプレート `zukai/slides/template.pptx` は `make_template.py` で作り直せる。フォントは Noto Sans JP（Google スライドで使える）。

記事の著者が変換後に手で直していた点のうち、コードを黒地に白文字にする、字が小さすぎる箇所を直す、子の箇条書きを○にする、の3つは最初から自動でやる。画像の貼り直しは、原稿の画像パスが手元にあれば要らない。記事のアドオンと違って Google スライドを直接編集はしないので、出力した .pptx を Google ドライブにアップロードして開く。

## アイコン付きのカード（cards）

Shodai Yanagimoto さんの投稿（https://x.com/shodaiiiiii/status/2114917442539618384 ）にあった、アイコン・見出し・一言のカードを並べるスライドを deck.js の型にした。投稿では better-icons（https://github.com/better-auth/better-icons ）を使って Claude にアイコンを選ばせている。

```bash
node zukai/fetch-icons.js search lightbulb --prefix lucide   # アイコンを探す（英語で）
node zukai/fetch-icons.js zukai/examples/icons.json          # データに書いたアイコンを zukai/icons/ に取ってくる
node zukai/deck.js zukai/examples/icons.json                 # zukai/out/icons/01-cards.png
```

データには `"icon": "lucide:lightbulb"` のように「アイコン集:名前」で書く。カードが3枚までなら1段、4枚なら2列×2段、5〜6枚なら3列×2段に並ぶ。

better-icons の中身は Iconify の公開 API（api.iconify.design）の検索と取得なので、fetch-icons.js は同じ API を curl で直接呼んでいる。取ってきた SVG は `zukai/icons/` に置き、アイコン集のライセンスを `zukai/icons/LICENSES.md` に書く（同梱の Lucide は ISC）。会話の中で Claude に直接探させたいなら、better-icons を MCP サーバーとして登録する。

```bash
claude mcp add better-icons -- npx -y better-icons@1.0.4
```

## 新しい資料が作れるかの検証

再現ではなく、新しい中身で同じ調子の資料が作れるかを確かめた。結果は `examples/kensho.json` から作った8枚の資料（`out/kensho/`）にまとめてある。中身は今回の作業で実測した数字だけで書いた。

```bash
node zukai/check.js zukai/out/kensho/html     # 崩れの検査
node zukai/stress.js                          # 型の余裕を測る（1分ほど）
```

check.js は書き出した HTML をブラウザで開いて、4種類の崩れを探す。

| 種類 | 中身 |
| --- | --- |
| overflow | 大きさの決まった箱から文字があふれている |
| outside | 文字がスライドの外か、下端のクレジット欄にかかっている |
| overlap | 別々に置いた文字同士が重なっている |
| orphan | 折り返しで1〜2文字だけが次の行に落ちている |

stress.js は、各スライドの文字を元の1倍から3倍まで伸ばして check.js にかける。最初は比較表・3CON・縦長図解が文字1.25倍で崩れていた。元の文章の長さぴったりに寸法を合わせていたからだ。そこで、箱に収まるまで字を縮める自動縮小を入れた（同じ種類の箱は同じ倍率にそろえ、7割で止める）。日本語は文節で折り返すようにもした。そのあとの結果がこれ。

| 型 | 崩れずに入る上限 |
| --- | --- |
| cover・slop・handoff・statement・expand・compare | 1.5倍 |
| process・three・縦長図解 | 1.25倍 |

2倍になると、どの型も崩れる。そこまで増えたら削るかスライドを分けるしかなく、そこは人の判断になる。

工程スライド（process）の補足欄は1列14字ほどしかない。「クリティカルシンキング」のような長いカタカナ語は、どう折り返しても割れる。元のスライドも同じ割れ方をしているので、再現版の 06-process は check.js で取り残しの指摘が1件残る。

## 同じ流れを自分の文章で回す

元のスライドから読み取れる手順は、思ったより雑でいい。最初のテキストは文章になっていなくていいし、指示も三言で済ませている。効いているのは、そのあとの4回の指摘のほうだと思う。

Claude（claude.ai でも Claude Design でもいい）に最初に渡すのは、こういう組み合わせ。

```
（言いたいことを箇条書きでも殴り書きでもいいので貼る）

これ、縦長4:3の画像一枚で、ビフォアフの認知変化で整理できない？
アートワークで作って
イラストはこれを使って（素材のファイルを添付）
```

初版が出たら、気になったところを一言ずつ返す。元の4回の指摘は、そのまま次の図解でも使い回せるチェックリストになっている。

- 図形と画像が重なっていないか
- 対応する項目は左右の矢印でつながっているか
- 色は属性（BEFORE と AFTER）で分かれているか
- タイトルは全体の象徴として一番濃いか
- 会話の場面は、チャットらしく雑談になっているか
- かたまりとかたまりの切れ目が余白で見えるか

良くなったら「まさにそういうこと」と言う。元のスライドが二つ目の見出しにわざわざ「たまに褒める」と入れているのは、何が当たりだったかを AI に伝えるためだろう。

このリポジトリの型に流し込みたいときは、殴り書きと一緒に次の依頼を Claude に渡すと `build.js` が読める JSON が返ってくる。

```
下のメモを、zukai/examples/ai_hanasu.json と同じ形の JSON にしてほしい。
BEFORE と AFTER は「考え方がどう変わるか」で対にする。
会話は BEFORE が用件だけで終わる2行、AFTER が雑談から本題に入る4行。
rows は左右で対になる3段にして、label はその段で比べている観点にする。
callout は身近なたとえ話を1つ。強調したい語は [[ ]] で囲む。
イラストは worker_tired / ai_blank / man_coffee / ai_desk / salesman_run から選ぶ。

（メモを貼る）
```
