# 睡眠用 歴史朗読動画の制作ツール

YouTubeの「sleep history」系、つまり2時間前後の歴史解説を低い声で淡々と語り、画面は絵画がゆっくり切り替わるだけの動画を、日本語で作るためのコマンドラインツール。台本はClaude、声は音声合成、動画はffmpegで組み立てる。

人の手が入る工程を1つだけ残してある。台本の事実確認と読み間違いの直し。ここを飛ばすと量産型のAI動画になり、収益化の審査で落ちる側に入る（後述）。

## 1日の流れ

```bash
python -m sleep_channel ideas                          # 題材の候補を10件
python -m sleep_channel new "江戸の長屋の一日"           # 章立て＋全12章の台本（数分）
# review.md を見て script/ch01.txt などを直す。画像を images/ に入れる
python -m sleep_channel approve 20261109
python -m sleep_channel build 20261109 --engine voicevox  # 音声→動画→概要欄
```

`out/video.mp4` と `out/metadata.txt`（タイトル案・概要欄・チャプター・タグ）ができるので、YouTube Studio で予約投稿する。`status` で全プロジェクトの進み具合が見られる。

台本づくりが途中で止まったら `script 20261109` で続きの章から書く。`build` は同じコマンドをもう一度打てば続きから動く。音声は章ごとに保存してあり、原稿を直した章だけ作り直す。

## 準備

```bash
pip install -r requirements.txt
# ffmpeg（macOS: brew install ffmpeg / Windows: winget install ffmpeg）
```

台本づくりに `ANTHROPIC_API_KEY`（または `ant auth login` のプロファイル）を使う。

## 声の選び方

| エンジン | 費用 | 準備 | 向いている場面 |
| --- | --- | --- | --- |
| `voicevox` | 無料。概要欄にクレジット必須 | VOICEVOX を起動しておく | 最初の10本。既定は低めの男性声 青山龍星（スタイルID 13） |
| `aivis` | 無料。モデルごとに規約が違う | AivisSpeech を起動しておく | VOICEVOXより自然な声が欲しいとき |
| `google` | Neural2 で100万字あたり約16ドル、毎月100万字まで無料枠ありとの集計（要確認） | `GOOGLE_TTS_API_KEY` | 毎日投稿でも費用をほぼゼロに抑えたいとき |
| `elevenlabs` | 日本語は1文字1クレジットが目安 | `ELEVENLABS_API_KEY` と `ELEVENLABS_VOICE_ID` | 声の質を最優先するとき |
| `dummy` | 無料 | なし | 無音で動画の組み立てだけ試す |

2時間の動画は約3万字になる。毎日出すと月90万字を超えるので、ElevenLabs だと上位プランが要る。元記事の手順はこの費用に触れていない。最初は VOICEVOX で出して、伸びた題材の系統が見えてから声に投資するほうが筋がいい。

VOICEVOX の声は `--speaker` でスタイルIDを変える。IDの一覧はエンジン起動中に http://127.0.0.1:50021/speakers で見られる。クレジットはこのツールが概要欄に自動で書く（`VOICEVOX:青山龍星` の形）。

## 画像

`images/` に置く。ファイル名を `ch03_長屋の間取り.jpg` のように章番号で始めると、その章の間に表示する。番号のない画像は、専用の画像がない章で `--slide-minutes`（既定4分）ごとに順番に使う。縦長の絵画は切らずに、ぼかした同じ絵で左右を埋める。

章ごとに内容に合った絵を2〜3枚用意するのがいちばん効く。1枚絵を2時間流すやり方は、YouTube のポリシーにある「最小限の物語しかない画像スライドショー」にそのまま当たる。

使う画像は著作権の切れた作品か、自分で権利を持つものにする。Wikimedia Commons、メトロポリタン美術館のオープンアクセス、国立文化財機構の ColBase、国立国会図書館デジタルコレクションに浮世絵や古地図が多い。利用条件を確かめて、出典を `images/credits.txt` に書いておけば概要欄に入る。

環境音は `bgm.mp3` をプロジェクトフォルダか作業フォルダ直下に置く。ナレーションより14LU小さくそろえて重ねる（`render` の音量は -20 LUFS 基準）。`--tail-minutes 30` でナレーションの後に環境音だけ流す時間を足せる。

## 台本の作り方

`new` はまず章立て（タイトル案3つ、概要、タグ、12章それぞれの要素）を作り、それから1章ずつ本文を書く。各章には直前の章の終わりを渡して続きとして書かせ、章立てで要素を割り振って重複を防ぐ。2時間ぶんを一度に書かせると後半が薄くなり、同じ話が繰り返されるので分けている。

本文と一緒に、確かめるべき事実（年号・人名・数値・諸説ある話）と、音声合成が読み間違えそうな語の読みを受け取る。どちらも `review.md` にまとまる。読みは音声にするときだけ置き換えるので、原稿は漢字のまま読める。足りない読みは `project.json` の `readings` に書き足す。

章立てを先に直したいときは `new --outline-only` で止め、`project.json` を編集してから `script` を実行する。気に入らない章は `script 20261109 --redo 3 7` で書き直す（承認は取り消される）。

チャンネルの方針は作業フォルダの `channel.json` で変える。項目は `name`、`concept`、`narrator`、`intro`、`outro`、`avoid`、`hashtags`。`intro` の `{theme}` はテーマに置き換わる。

## 収益化について先に知っておくこと

YouTube は2025年7月に「繰り返しの多いコンテンツ」のポリシーを「不自然なコンテンツ（inauthentic content）」に改め、次のものを収益化の対象外と明記した。

- 物語・解説・教育的価値が最小限か皆無の画像スライドショーや、型にはまった筋書き
- 量産を思わせる、汎用的な型で作ったAI生成コンテンツ
- 自分が作っていない文章の朗読だけで構成されたもの

AI音声そのものは禁止されていない。見られるのは、1本ごとに中身と手間が入っているかどうか。このツールが章ごとの画像、事実確認、承認の工程を挟んでいるのはそのため。青空文庫の朗読だけで作る、毎日同じ構成の動画を自動で流す、といった運用は避ける。

元記事が引くFortuneの事例（年70万ドル）は、5つのチャンネルを給与制の小さなチームで回し、月6,500ドルの経費をかけている。1人が毎朝20分で到達した数字ではない。本人も個人がAIの長尺動画で稼げるのは2027年ごろまでと見ている。

収益化の条件は登録者1,000人と直近12か月の総再生時間4,000時間。2時間の動画は再生時間が積み上がりやすいので、この条件に届く速さが睡眠動画のいちばんの強み。

## 環境変数

| 変数 | 内容 | 既定値 |
| --- | --- | --- |
| `SLEEP_CHANNEL_DIR` | 作業フォルダ | `./sleep_projects` |
| `SLEEP_MODEL` | 台本に使うモデル | `claude-opus-5-5` |
| `SLEEP_EFFORT` | 台本の思考量 | `medium` |
| `SLEEP_CPM` | 1分あたりの文字数（尺の見積もりと dummy の長さ） | `270` |
| `VOICEVOX_URL` / `VOICEVOX_SPEAKER` | VOICEVOX ENGINE の場所と声 | `http://127.0.0.1:50021` / `13` |
| `AIVIS_URL` / `AIVIS_SPEAKER` | AivisSpeech Engine の場所と声 | `http://127.0.0.1:10101` / `888753760` |
| `GOOGLE_TTS_API_KEY` / `GOOGLE_TTS_VOICE` | Google の鍵と声 | なし / `ja-JP-Neural2-D` |
| `ELEVENLABS_API_KEY` / `ELEVENLABS_VOICE_ID` / `ELEVENLABS_MODEL` | ElevenLabs の鍵・声・モデル | なし / なし / `eleven_multilingual_v2` |

## 動画の組み立て方

静止画を2時間ぶん24fpsでそのまま符号化すると、4コアの環境で30分前後かかる。そこで画像ごとにフェードイン、30秒の静止、端数、フェードアウトの部品だけを符号化し、静止部分は同じ部品を並べてストリームコピーでつなぐ。同じ環境で、1080p・24fps・86分（画像25回切り替え、環境音あり）の書き出しが5分で終わった。フレーム数は章の境目から累積で計算するので、2時間たっても音と絵がずれない。中間ファイルは `work/` に残り、画像を差し替えなければ次回は再利用する。

## テスト

```bash
python -m pytest tests/test_sleep_channel.py
```

Claude と音声合成APIは偽物に差し替えていて、外へは通信しない。ffmpeg があれば小さな動画を実際に書き出して、長さと音声・映像のストリームを確かめる。
